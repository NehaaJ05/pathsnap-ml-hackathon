# PathSnap — distributed map-matching & route reconstruction

UE24CS352A Machine Learning hackathon. Pipeline: GPS observations → candidate road arcs → classifier
→ HMM/Viterbi route → evaluation → FastAPI backend and evaluator UI.

## Layout

```
src/pathsnap/      library: data loading, candidates & features, metrics, HMM decoder, pipeline
scripts/           numbered pipeline steps (run in order, see below)
api/app.py         FastAPI backend (Laptop 1)
ui/index.html      evaluator interface (Laptop 2)
models/            trained classifiers (joblib), frozen HMM config (hmm_config.json)
results/           metrics/, plots/, maps/ (Folium HTML), tables/, data/, logs/
report/            technical report draft (Markdown, DOCX, PDF)
```

## Setup

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

Raw data path is set in the scripts (`DATA = ".../Student folder"`); change it if your copy lives elsewhere.

## Run the pipeline

```bash
./venv/bin/python scripts/01_build_features.py      # candidates, features, dataset inventory
./venv/bin/python scripts/02_train_compare.py      # 6 models: 5-fold group CV + student test
N_TRIALS=20 ./venv/bin/python scripts/04_bayes_opt.py   # Bayesian search (Optuna TPE), untuned baseline
./venv/bin/python scripts/07_finalize_tuned.py     # OOF probabilities for tuned model; final_model.joblib
./venv/bin/python scripts/03_hmm_eval.py           # HMM tuning on training trips; student-test comparison
./venv/bin/python scripts/08_train_vs_test.py      # training-trip scores (over/underfitting)
./venv/bin/python scripts/05_figures_maps.py       # figures and Folium maps
./venv/bin/python scripts/06_report_tables.py      # Markdown tables for the report
```

Random seed is 42 everywhere. Step 02 takes about 20 minutes on 2 CPUs (the MLP dominates).
`cache/` is regenerated by step 01 and is not committed.

## Run the API and UI

Evaluator trips go in `<PATHSNAP_EVAL_ROOT>/evaluator_test/<trip_id>/` with the same file layout as
the training data. The evaluator's reference routes must stay on the server.

```bash
PATHSNAP_EVAL_ROOT=/path/to/evaluator_root \
  ./venv/bin/python -m uvicorn api.app:app --host 0.0.0.0 --port 8000
```

- `GET /health`, `GET /trips`, `POST /predict {"trip_id": "..."}`
- Requests are logged to `logs/api_requests.log` (and to the console).
- On Laptop 2, open `ui/index.html` and set the API URL to Laptop 1's address.

To test the API on the student-test trips instead:
`PATHSNAP_EVAL_ROOT=<student folder> PATHSNAP_EVAL_PARTITION=student_test`.

## Design notes

- **Labels:** a GPS observation's reference arc is the nearest arc of the reference route. Candidates
  are generated without labels, and the prediction path never reads the reference route.
- **Final classifier:** HistGradientBoosting with Bayesian-tuned hyperparameters (`results/metrics/final_model.json`).
- **Decoder:** β = 5 m, unreachable penalty 20, gap threshold 30 s, tuned on training trips only (`models/hmm_config.json`).
- **Evaluator data:** not used during development and never read by any development script.
